# 密行列の線形代数

**この章が Rust 的には本丸である。** 最も時間をかける。

数学として新しいことは少ないが、**「行列を所有する」「行列の一部を借りる」を
Rust の借用規則の中で表現する**という問題が初めて本格的に出る。
配列を破壊しながら分解を進める古典的な作法が、そのままでは借用検査を通らない。

## 条件数——問題の側の性質

\\(Ax = b\\) を解く。\\(b\\) に摂動 \\(\delta b\\) が乗ったとき、解の摂動は

\\[
\frac{\\|\delta x\\|}{\\|x\\|} \le \kappa(A) \frac{\\|\delta b\\|}{\\|b\\|},
\qquad \kappa(A) = \\|A\\|\\,\\|A^{-1}\\|
\\]

**条件数はアルゴリズムの性質ではなく問題の性質である。** \\(\kappa(A) = 10^{10}\\) なら、
入力が `f64` に丸まった時点（相対誤差 \\(10^{-16}\\)）で解は \\(10^{-6}\\) しか信用できない。
どんな解法を使ってもこれは改善しない。**アルゴリズムを疑う前に条件数を見る。**

以下 \\(\\|\cdot\\|\\) はベクトルノルムから誘導される作用素ノルムとする。上の摂動評価も
\\(\kappa \ge 1\\) も、これを前提にしている（\\(\\|I\\| = 1\\) と \\(\\|AB\\| \le \\|A\\|\\|B\\|\\) を使う）。
Frobenius ノルムでは \\(\kappa_F(I) = n\\) となって成り立たない。
添字なしの \\(\kappa\\) は任意の誘導ノルム、\\(\kappa_2\\) は2-ノルムの場合を指す。

直交行列は \\(\kappa_2 = 1\\)。ここが後で効く。

### 後退安定性

Wilkinson の枠組み。前進誤差（計算した解と真の解の差）を直接評価するのは難しいので、
問いを裏返す。

> **計算した解 \\(\hat x\\) は、どれくらい摂動した問題の厳密解か。**

\\((A + \delta A)\hat x = b\\) を満たす \\(\delta A\\) が \\(\\|\delta A\\| = O(u)\\|A\\|\\) に収まるとき、
そのアルゴリズムは**後退安定**（backward stable）という。「丸めは入力の微小な摂動と等価だった」と言えるなら、
アルゴリズムはそれ以上の罪を犯していない。

そして前進誤差は条件数と掛け算になる:

\\[
\frac{\\|\hat x - x\\|}{\\|x\\|} \lesssim \kappa(A) \cdot u
\\]

**後退安定なアルゴリズムでも、条件数が悪ければ答えは悪い。**
「安定」と「正確」は別物で、責任の所在が違う（アルゴリズム側か、問題側か）。

なお、[常微分方程式](ch04-ode.md)の A-安定性、[偏微分方程式](ch08-pde.md)の von Neumann 安定性は名前が同じだけの**別概念**である。
1つの章に括らないのはこのためで、必要になった章の入口でその都度復習する。

## 分解

### LU 分解と部分ピボット選択

Gauss の消去法は、\\(A\\) を下三角 \\(L\\)（対角 1）と上三角 \\(U\\) の積に分解する操作そのものである。
分解しておけば、右辺 \\(b\\) が変わっても前進代入・後退代入の \\(O(n^2)\\) だけで解ける
（分解自体は \\(O(n^3)\\)。後述の flop 表を参照）。

ピボットが必要な理由は2つあり、混同されやすい。

1. ピボットがゼロだと割れない——これは自明
2. ピボットが小さいと誤差が増幅する——こちらが本質。小さい数で割ると
   乗数が巨大になり、消去の過程で元の情報が桁落ちで消える

第 \\(k\\) 列の**第 \\(k\\) 行以降**で絶対値最大の要素を選んで行を入れ替えるのが部分ピボット選択で
（消去済みの上の行を候補に入れると分解が壊れる）、
乗数の絶対値が 1 以下に抑えられる。結果は \\(PA = LU\\) の形になる。
実用上ほぼ常に安定だが、理論上は成長因子が \\(2^{n-1}\\) まで大きくなりうる
（Wilkinson の例）。実際にそうなる行列は病的で、実務で遭遇しない。

`proptest` の不変量としては \\(PA = LU\\) の再構成が使える——
分解した後に掛け戻して元に戻るか。正解を用意せずに広い入力を叩ける。

### QR 分解と Householder

\\(A = QR\\)、\\(Q\\) は直交、\\(R\\) は上三角。\\(\kappa_2(Q) = 1\\) なので、
**直交変換は誤差を増幅しない。** これが QR が数値的に好まれる理由である。

作り方が3つあり、安定性が違う。

| 方法 | 安定性 |
|---|---|
| 古典的 Gram–Schmidt | 直交性が壊滅的に失われる。使わない |
| 修正 Gram–Schmidt (MGS) | ましだが、\\(Q\\) の直交性の誤差が \\(\kappa(A) u\\) に比例する |
| Householder 鏡映 | 後退安定。\\(Q\\) の直交性は \\(\kappa\\) に依らず \\(O(u)\\) |

Householder は「ベクトルを軸方向に叩き潰す鏡映」\\(H = I - 2vv^\top/(v^\top v)\\) を
左から順に掛けていく。各 \\(H\\) は直交かつ対称。

\\(Q\\) を陽に作らないのが普通である。\\(A\\) が \\(m\times n\\) のとき、
鏡映ベクトル \\(v\\) を \\(n\\) 本持っておけば（合計 \\(mn\\) 個の数）
\\(Q^\top b\\) は逐次適用で計算でき、\\(Q\\) を \\(m^2\\) 個の数として持つ必要がない。
「行列を持たずに行列の作用だけを持つ」という発想で、[有限要素法](ch08b-fem.md)の matrix-free に繋がる。

### 最小二乗——正規方程式を使ってはいけない

\\(\min_x \\|Ax - b\\|_2\\)（\\(A\\) は縦長）。微分してゼロと置けば正規方程式

\\[
A^\top A\, x = A^\top b
\\]

が出る。数学的には正しい。**数値的には使ってはいけない。** 理由は

\\[
\kappa_2(A^\top A) = \kappa_2(A)^2
\\]

**条件数が二乗される。** \\(\kappa(A) = 10^8\\) の問題は、正規方程式に直した瞬間に
\\(\kappa = 10^{16}\\) になり、`f64` では情報が残らない。**問題が悪いのではなく、
解法が問題を悪くしている。**

正しくは \\(A = QR\\) と分解して \\(\hat Rx = \hat Q^\top b\\) を解く。
\\(A\\) が \\(m\times n\\)（\\(m>n\\)）のとき full QR の \\(Q\\) は \\(m\times m\\)、\\(R\\) は \\(m\times n\\) なので、
実際に使うのは \\(R\\) の上 \\(n\times n\\) ブロック \\(\hat R\\) と \\(Q^\top b\\) の先頭 \\(n\\) 成分である。
おまけとして、\\(Q^\top b\\) の下 \\(m-n\\) 成分のノルムが残差ノルムになる——追加計算なしで出る。
ランク落ちが疑われるなら SVD を使う。

### ただし「\\(\kappa\\) のまま」は残差が小さいときだけ

ここは正確に書く必要がある。**最小二乗問題そのものの条件数**は

\\[
\frac{2\kappa_2(A)}{\cos\theta} + \kappa_2(A)^2\tan\theta,
\qquad \theta = \angle(b, \mathrm{range}(A))
\\]

これは \\(A\\) と \\(b\\) を**同時に**相対 \\(\varepsilon\\) で摂動したときの感度である
（Golub–Van Loan, Matrix Computations の最小二乗の摂動定理）。\\(b\\) だけを摂動するなら \\(\kappa/\cos\theta\\) の項しか出ず、
\\(\kappa^2\\) は現れない。\\(\kappa^2\tan\theta\\) は \\(A\\) の摂動から来る。

で、**残差が大きい（\\(\theta\\) が大きい）と \\(\kappa^2\\) の項が復活する。**
これは後退安定性の問題ではなく問題側の感度なので、**どんな安定な解法でも消せない。**

これは実測できる。縦長の悪条件行列（\\(A_{ij}=1/(i+j+1)\\) など）で \\(\tan\theta\\) を振ると、
Householder QR の誤差が、**\\(\tan\theta\\) に比例して増える**。残差ゼロなら \\(\kappa u\\) のオーダーに収まり、
\\(\tan\theta\\) を上げると \\(\kappa^2 u \tan\theta\\) が支配する。

**実験を組むとき、残差 \\(r\\) は解くのに使う QR とは独立に作ること。**
分解で得た \\(\hat Q\\) の後ろの列から \\(r\\) を作ると、\\(r\\) が**計算された** range と
厳密に直交してしまい、\\(\kappa^2\\) を生む「真の range とのずれ」が打ち消えて現象が消える。
厳密有理数で正規方程式を解いて \\(r = b - Ac\\) を作るのが確実である。したがって「QR なら \\(\kappa\\) のまま」が言えるのは
**残差が小さい問題に限る。** 正規方程式が悪いのは解法の罪、残差が大きいときの
\\(\kappa^2\tan\theta\\) は問題の性質——この章の主題そのものの対比がここにある。

この章の完了条件は**前節の \\(\kappa\\) 対 \\(\kappa^2\\) の対比を実測すること**である——
Hilbert 行列のような条件数の悪い行列で、正規方程式版と QR 版の精度差を出す。
残差のある最小二乗（この \\(\kappa^2\tan\theta\\) のほう）は、そこに足す第2の課題になる。

### Cholesky

\\(A\\) が対称正定値なら \\(A = LL^\top\\) と分解でき、計算量は LU の半分、
ピボットが要らない（正定値性が安定性を保証する）。

**正定値でないと \\(\sqrt{\text{負}}\\) が出て落ちる。** これは実務で頻繁に起きる:
推定した共分散行列は理論上半正定値だが、**サンプル数が次元より少なかったり、
丸め誤差が乗ったりすると数値的に非正定値になる。** 金融のリスク計算で有名な実害で、
ガウス過程の共分散行列の対角に jitter を足すのも同じ問題への対処である。

つまり **Cholesky が落ちるかどうかが、行列が正定値かどうかの実用的な判定になっている。**
失敗を `Result` で返す設計が自然に要求される場所である。

### SVD

\\(A = U\Sigma V^\top\\)。特異値 \\(\sigma_1 \ge \cdots \ge \sigma_n \ge 0\\) が、
\\(A\\) の作用を「回転・スケール・回転」に分解する。

- \\(\kappa_2(A) = \sigma_1/\sigma_n\\)——条件数の定義そのものが特異値で書ける
- ランクは非ゼロの特異値の個数。数値的には「\\(\sigma_i > \text{tol}\\) の個数」で、
  どこで切るかが判断になる
- 擬似逆行列、低ランク近似（Eckart–Young）、PCA が全部ここから出る

計算量は LU/QR と同じ \\(O(n^3)\\) だが定数倍が重い。**必要なときだけ使う。**

どう計算するかは[固有値問題](ch02b-eigen.md)で扱う。\\(A^\top A\\) の固有値問題に見えるが、
**その行列を作ってはいけない**——上の \\(\kappa^2\\) がそのまま効く。

## 反復法

\\(n\\) が大きい、あるいは \\(A\\) が疎なら、\\(O(n^3)\\) の直接法は使えない。

- Jacobi / Gauss–Seidel: \\(A = M - N\\) と分割して \\(x_{k+1} = M^{-1}(Nx_k + b)\\)。
  収束条件は反復行列 \\(M^{-1}N\\) のスペクトル半径が 1 未満。
  対角優位なら収束する。[根の探索](ch01-roots.md)の不動点反復の行列版である
- 共役勾配法 (CG): 対称正定値専用。厳密算術では \\(n\\) 回で終わるが、
  実際には反復法として使う。誤差の評価は

\\[
\frac{\\|e_k\\|_A}{\\|e_0\\|_A} \le 2\left(\frac{\sqrt\kappa - 1}{\sqrt\kappa + 1}\right)^k,
\qquad \\|e\\|_A = \sqrt{e^\top A e}
\\]

  3点を落とさないこと。**\\(A\\)-ノルムであること**（2-ノルムでは成立しない）、
  **係数 2 が要ること**、そして**これは上界であって収束率ではないこと**。
  係数 2 は飾りではない。区間 \\([1,\kappa]\\) 上の厳密な minimax から、
  係数を落とした形に対する比は \\(2/(1+\sigma^{2k})\\)（\\(\sigma = (\sqrt\kappa-1)/(\sqrt\kappa+1)\\)）
  で、**\\(k\\) を上げると 2 に近づく**（達成はしない）。\\(k\\) が小さいうちは 1 に近いので、
  小さい \\(k\\) だけ見て「2 は要らない」と判断しないこと。

  そして実際の減衰は上界よりずっと速いことが多く、どれだけ速いかは
  **スペクトルの分布で1桁変わる**（固有値が一様に散っているか、クラスタしているか）。

  値打ちは \\(\kappa\\) ではなく \\(\sqrt\kappa\\) が効くことで、
  前処理（preconditioning）は \\(\kappa\\) を下げてこの指数を稼ぐ操作である。
  前処理にはもう一つの効き方があり、**固有値をクラスタさせる**と上界とは無関係に速くなる。

**CG は \\(A\\) そのものを要求しない。** 必要なのは \\(v \mapsto Av\\) だけである。
この事実を Rust のトレイトで表現すると matrix-free になる——[有限要素法](ch08b-fem.md)で回収する。

## 逆行列は作らない

\\(x = A^{-1}b\\) と書くのは数学の記法であって、計算の手順ではない。

ここは \\(O\\) 記法では比が見えないので flop 数で書く（\\(O\\) の中に定数を書くのは矛盾でもある）。

| 操作 | flop |
|---|---|
| LU 分解 | \\(\tfrac23 n^3\\) |
| Cholesky 分解 | \\(\tfrac13 n^3\\)（LU の半分） |
| 逆行列の計算 | \\(2n^3\\)（LU の3倍） |
| 逆行列を掛ける | \\(2n^2\\) |
| 三角系を解く（前進+後退） | \\(2n^2\\)（同じ） |

- 逆行列を作ると分解そのものより高くつく
- 掛けるコストは三角系を解くのと同じで、得がない
- 精度も逆行列経由のほうが悪い

\\(A^{-1}\\) 自体が答えである場合を除いて、作る理由がない。
API 設計としては「`inverse()` を生やさない、あるいは目立たせない」という判断になる。

## Rust の言語機構

### 借用を分割する

LU 分解の内側で起きることを借用の言葉で書くと、こうなる。

> ピボット行を**読みながら**、その下の行を**書き換える**。

素朴に書くと、同じ `&mut [f64]` から不変参照と可変参照を同時に取ることになり、
**借用検査に落ちる。** 実行時には別の行なので競合していないのだが、
コンパイラにはそれが分からない。

言語側の答えが `split_at_mut` である。

```rust
let v = &mut [1.0f64, 2.0, 3.0, 4.0][..];
let (head, tail) = v.split_at_mut(2);   // 2本の &mut [f64] が同時に生きる
head[0] = tail[0];                       // 片方を読みながら片方を書ける
```

**重なりのない2つの可変借用に割る**ことで、コンパイラに独立性を教えている。
`ndarray` の `multi_slice_mut` / `split_at`、`chunks_mut`、`iter_mut` も同じ役割を果たす。

「これは安全なはずなのにコンパイラが通さない」と感じたら、
たいてい**独立性を型で示す道具が用意されている**。`unsafe` に逃げる前に探す。

### in-place 分解

LU の古典的な作法は、**入力行列を破壊して同じメモリに \\(L\\) と \\(U\\) を詰める**ことである。
\\(L\\) の対角は 1 と分かっているので格納しなくてよく、下三角に \\(L\\)、
上三角に \\(U\\) がちょうど収まる。追加のメモリがゼロになる。

これを Rust で表現する形が複数ある。

| 形 | 得られるもの / 失うもの |
|---|---|
| `fn lu(&mut self)` | 確保ゼロ。元の \\(A\\) が消える。分解結果の意味が型に出ない |
| `fn lu(self) -> Lu` | 所有権を移すので元の \\(A\\) を誤って使えない。型で「分解済み」を表せる |
| `fn lu(&self) -> Lu` | \\(A\\) が残る。確保が要る |

`fn lu(self) -> Lu` が Rust らしい——**所有権の移動で「この行列はもう分解に使われた」を型システムに載せる。**
ただしパックされた \\(L\\)/\\(U\\) を取り出す API が要る。

### ビューとストライド

部分行列を「コピーせずに借りる」には、開始位置・形・**ストライド**（次の行/列へ何要素進むか）が要る。
`ndarray` の `ArrayView` / `ArrayViewMut` はこれを型として持っている。
自前の `Matrix` から始めると、部分行列を渡すたびにコピーするか、
インデックスの計算を呼び出し側に押し付けるかになり、**何が解決されているのかが分かる。**

### 行の交換をどう表現するか

部分ピボット選択で行を入れ替えるとき、選択肢が2つある。

- データを実際に動かす——以降のアクセスが素直。交換のコストが \\(O(n)\\)
- 置換ベクトル \\(p\\) を持つ——交換は \\(O(1)\\)。以降のアクセスが全部 `a[p[i]][j]` になり、
  メモリアクセスが不連続になってキャッシュに悪い

計算量では後者が有利に見えるが、実測すると前者が勝つことがある。
これは「アルゴリズムの計算量」と「実際の速度」が食い違う典型で、
測らずに決められない類の判断である。

### 行優先か列優先か

C と Rust の配列は行優先、Fortran と LAPACK と BLAS は**列優先**である。
`nalgebra` と `faer` は列優先を採る（BLAS/LAPACK に渡しやすい）。
`ndarray` は既定で行優先だが両方扱える。

効くのは**内側のループがメモリ上で連続に進むか**である。
列優先の行列を行方向に走査すると、1要素ごとに \\(n\\) 要素分ジャンプして
キャッシュラインを毎回捨てる。同じ \\(O(n^3)\\) の演算が数倍変わる。

### クレートの三択

**この選択自体が最初の課題である。**

| | 位置づけ |
|---|---|
| `ndarray` | NumPy 相当の n 次元配列。動的サイズ、任意次元、ビューが強い |
| `nalgebra` | 固定サイズが型に載る（`Matrix3<f64>` 等）。幾何・グラフィクス寄り。小さい行列で速い |
| `faer` | pure Rust の高性能密行列。`sparse` と `matrix_free` を持つ。[有限要素法](ch08b-fem.md)まで見据えるとここが繋がる |

**まず自前の最小 `Matrix` 型を書いてから既製品に移ると、何が解決されているかが分かる。**
ビュー、ストライド、ブロードキャスト、BLAS への委譲——不便を自分で踏んでから見る。

## オラクル

**この章から scipy が本格的に要る。** `scipy.linalg` の `lu` / `qr` / `svd` / `cholesky` で
値を生成して定数として埋め込む（テスト実行時に Python を呼ばない）。
現時点で `uv` は未導入なので、ここが導入の契機になる。

相互検証として `faer` の結果と突き合わせる形も取れる。

Hilbert 行列 \\(H_{ij} = 1/(i+j+1)\\)（\\(i,j\\) は 0 始まり。1 始まりなら \\(1/(i+j-1)\\)）は
条件数が悪いことで有名で、
\\(n\\) とともに条件数が指数的に増大する。逆行列は整数成分の閉じた形を持つので
厳密値と比較できる。具体的な条件数の値は scipy を入れた時点で生成すること
——**記憶で書いた数字を埋めない。**

不変量（`proptest` 向け）:

- \\(PA = LU\\) の再構成
- \\(Q^\top Q = I\\)、\\(QR = A\\)
- \\(LL^\top = A\\)（正定値な入力を生成する必要がある。\\(B^\top B + \epsilon I\\) で作れる）
- \\(Ax = b\\) を解いた \\(x\\) について残差 \\(\\|Ax - b\\|\\) が小さい

4. 行の交換をデータの移動でやるか置換ベクトルでやるか
5. 行優先か列優先か
6. Cholesky の失敗（非正定値）をどう返すか

## 完了条件

**Hilbert 行列で、正規方程式版と QR 版の最小二乗の精度差を実測して見せる。**

条件数が \\(\kappa\\) の問題で、正規方程式版の誤差が \\(\kappa^2 u\\)、QR 版が \\(\kappa u\\) で抑えられる
（「そのオーダーになる」ではない——実測は上界よりかなり良い）。

**崩れ方が2種類あることを先に知っておくこと。** 正方 Hilbert \\(H_n\\)、
\\(x_{\text{true}} = (1,\ldots,1)\\)、\\(b = Hx\\) で解くと、\\(n\\) を上げるにつれて
正規方程式版の誤差は桁単位で急速に悪化し、QR 版は同じ範囲で精度を保つ。
先に音を上げるのは正規方程式版で、\\(H^\top H\\) の Cholesky が落ちて解けなくなる。
QR 版はそこからさらに大きい \\(n\\) まで解け、最後に有効数字が尽きる。

**段階的な精度差が見えるのは \\(n\\) が小さいうちだけ**で、そこを過ぎると
\\(H^\top H\\) が数値的に非正定値になって Cholesky が失敗する。これは失敗ではなく観察対象で、
「Cholesky が落ちるかどうかが正定値性の実用的な判定になっている」という前述の話がここに出る。

**どの \\(n\\) で落ちるかは \\(H^\top H\\) の総和順序に依存し、実装で動く。**
これ自体が \\(\kappa^2 u \approx 1\\) の境目にいる証拠で、
「落ちる最小の \\(n\\) を見つける」を課題にするなら、答えが実装で動くことごと観察対象にする。

もう一点。Hilbert 行列は正方なので、これは厳密には最小二乗ではなく連立一次方程式である
（残差ゼロ）。\\(\kappa u\\) と \\(\kappa^2 u\\) の対比は綺麗に出るが、
残差のある最小二乗を測るなら縦長の行列（たとえば \\(A_{ij} = 1/(i+j+1)\\)、\\(m = 2n\\)）を使う。
そちらでは前述の \\(\kappa^2\tan\theta\\) の効果も一緒に見える。

# 最適化

\\(\min_{x \in \mathbb{R}^n} f(x)\\)。制約なしを主に扱う。

**章1の Newton 法の多変数版**が骨格で、各反復の内側で**章2の線形方程式**を解く。
そして勾配をどう手に入れるかが**章6**に繋がる。この章は接続点である。

## 勾配降下と、なぜジグザグするか

\\[
x_{k+1} = x_k - \alpha_k \nabla f(x_k)
\\]

最急降下方向は「その点で最も速く下る方向」だが、一歩先までしか見ていない。

二次形式 \\(f(x) = \frac12 x^\top A x\\)（\\(A\\) は対称正定値）で最適な \\(\alpha\\) を各ステップで選んでも、
1反復あたりの減衰は

\\[
\frac{f(x_{k+1}) - f^\*}{f(x_k) - f^\*} \le \left(\frac{\kappa - 1}{\kappa + 1}\right)^2,
\qquad
\frac{\\|e_{k+1}\\|_A}{\\|e_k\\|_A} \le \frac{\kappa - 1}{\kappa + 1},
\qquad \kappa = \kappa_2(A)
\\]

**何について測るかで指数が2倍違う。** 2乗が付くのは**関数値**のほうで、
誤差ノルム \\(\\|e\\|_A\\) は2乗しない（\\(f - f^\* = \frac12\\|e\\|_A^2\\) なので当然である）。
これは**最悪初期値に対する上界**（Kantorovich 不等式）である。等号が成立するのは
\\(A\\) の最大・最小固有ベクトル成分について \\(|g_1| = |g_2|\\) となる初期値で、
そこでは \\(\kappa\\) の値に依らず上の2式に機械精度で一致する。
素直な初期値ではこれを大きく下回る（数桁速い）。

\\(\kappa\\) が大きいと \\((\kappa-1)/(\kappa+1) \to 1\\) で、ほとんど減らない。
細長い谷を斜めに横切っては跳ね返る「ジグザグ」の正体がこれで、
**問題の条件数がそのまま収束速度になっている。**

章2の共役勾配法と比べるときは、**両方を \\(A\\)-ノルムに揃える。**

| 手法 | \\(\\|e_k\\|_A/\\|e_0\\|_A\\) の上界 |
|---|---|
| 最急降下 | \\(\left(\frac{\kappa-1}{\kappa+1}\right)^k\\) |
| 共役勾配法 | \\(2\left(\frac{\sqrt\kappa-1}{\sqrt\kappa+1}\right)^k\\) |

**\\(\kappa\\) が \\(\sqrt\kappa\\) に変わる。** CG が
過去の方向と共役になるよう方向を選び直しているからで、同じ \\(\kappa\\) の問題でも
方向の選び方で指数が変わる。片方を関数値、片方を誤差ノルムで比べると
この対比が成立しないので、揃えること。

## Newton 法

\\(f\\) を2次まで展開したモデルを最小化する。

\\[
x_{k+1} = x_k - H(x_k)^{-1}\nabla f(x_k), \qquad H = \nabla^2 f
\\]

章1と同じく2次収束だが、**目的関数に課される条件は章1より1段強い。**
最適点で \\(H\\) が正則、初期値が十分近い、に加えて——
**\\(\nabla^2 f\\) が \\(x^\*\\) の近傍で Lipschitz 連続**が要る。
\\(f \in C^2\\)（\\(\nabla^2 f\\) が連続なだけ）では超1次収束までしか言えない。

これは多変数だからではない。ここで求根しているのは \\(f\\) ではなく \\(\nabla f\\) なので、
章1の「求根写像のヤコビ行列が Lipschitz」を \\(F = \nabla f\\) に当てはめると
\\(\nabla^2 f\\) の Lipschitz 連続性になる、というだけである——**1変数の最適化でも同じ**。

問題は次のとおりである。

1. \\(H\\) が正定値でないと降下方向にならない。鞍点付近では
   \\(-H^{-1}\nabla f\\) が上り方向を向きうる。対処は \\(H + \lambda I\\)（\\(\lambda\\) を
   正定値になるまで上げる）や修正 Cholesky で、
   **\\(\lambda \to \infty\\) の極限が勾配降下**になる。信頼領域法はこれを別の角度から定式化したものである
2. \\(H\\) の計算が高い。\\(n(n+1)/2\\) 個の2階偏導関数が要る
3. 各反復で \\(n \times n\\) の系を解く（\\(O(n^3)\\)）。
   **逆行列は作らない**——章2のとおり \\(H d = -\nabla f\\) を解く

`inverse()` を書きたくなるのはここだが、書かない。

## 準 Newton 法

\\(H\\) を計算せず、過去の勾配の変化から近似を組み上げる。

\\(s_k = x_{k+1}-x_k\\)、\\(y_k = \nabla f(x_{k+1}) - \nabla f(x_k)\\) と置くと、
2次近似が正しければ \\(H s_k \approx y_k\\)。この割線条件を満たす近似 \\(B_{k+1}\\) を、
\\(B_k\\) からできるだけ動かさずに作る——章1の割線法の多変数版である。

BFGS 更新は正定値性を保つ。保つ条件が

\\[
s_k^\top y_k > 0 \qquad (\text{曲率条件})
\\]

で、これは直線探索の Wolfe 条件から自動的に満たされる。**直線探索の条件と
更新式の正定値性が結びついている**のがこの手法の設計上の要点で、
片方だけ実装すると壊れる。

### L-BFGS

BFGS は \\(n\times n\\) の近似を持つので \\(n\\) が大きいと保持できない。
L-BFGS は直近 \\(m\\) 組の \\((s_k, y_k)\\) だけ持ち（\\(m\\) は \\(n\\) に比べて小さい定数）、
\\(B_k\\) もその逆行列も陽に作らずに、探索方向 \\(B_k^{-1}\nabla f\\) を
two-loop recursion で直接計算する。
メモリが \\(O(mn)\\) に落ちる。

履歴の持ち方がそのまま Rust のデータ構造の選択になる——
`VecDeque` で push/pop するか、固定長のリングバッファを自分で回すか。

## 直線探索

方向 \\(d_k\\) を決めた後、どれだけ進むか \\(\alpha\\) を決める。
厳密に最小化する必要はない（それ自体が1次元最適化問題になって高い）。
「十分よい \\(\alpha\\)」の条件を挙げる。

- Armijo 条件（十分減少）:
  \\(f(x_k + \alpha d_k) \le f(x_k) + c_1 \alpha \nabla f_k^\top d_k\\)、\\(c_1\\) は 1 より十分小さい正の定数。
  減りが足りない \\(\alpha\\) を弾く
- 曲率条件: \\(\nabla f(x_k+\alpha d_k)^\top d_k \ge c_2 \nabla f_k^\top d_k\\)、\\(c_2\\) は 1 に近い正の定数（\\(0 < c_1 < c_2 < 1\\)）。
  小さすぎる \\(\alpha\\) を弾く

両方合わせて Wolfe 条件。Armijo だけだと \\(\alpha \to 0\\) で常に満たされてしまい進まない。
実装は backtracking（\\(\alpha\\) を \\(\rho\\) 倍しながら Armijo を満たすまで縮める）が最も単純である。

信頼領域法は逆向きのアプローチで、先に「モデルを信用する半径」を決め、
その中でモデルを最小化する。ステップが良ければ半径を広げ、悪ければ縮める。
方向を決めてから長さを決める（直線探索）か、長さの上限を決めてから方向を決める（信頼領域）か、
という対比である。

## 決定論的最適化と確率的最適化の断絶

ここは数値解析だけを追うと見えない対比である。

**数値解析の最適化は「収束させる」ものである。** 停止条件は \\(\\|\nabla f\\| < \varepsilon\\) で、
反復を重ねるほど良くなることが期待される。

**SGD は本質的に収束させない。** 目的関数が期待値 \\(\mathbb{E}[\ell(x;\xi)]\\) で、
各ステップで見るのはその不偏推定でしかない。勾配のノイズは消えず、
学習率を下げない限り最適点のまわりを漂い続ける。そして**そのノイズが正則化として働く**
——ノイズを消しきると汎化が悪くなることがある。

同じ「最適化」の看板の下で、**目的関数が確定的か期待値かで作法が真逆になる。**
決定論の側では「収束しないこと」はバグだが、確率的な側ではそれが仕様である。

なお、**最尤推定はそのまま最適化である。** 統計の計算的な核がここに落ちる。
最適化するのは**負の**対数尤度 \\(-\ell\\) で、その Hessian \\(-\nabla^2\ell(\hat\theta)\\) が
**観測情報行列**、その期待値 \\(I(\theta) = -\mathbb{E}[\nabla^2\ell(\theta)] = \mathbb{E}[\nabla\ell\,\nabla\ell^\top]\\)
が **Fisher 情報行列**である。そして \\(I(\theta)^{-1}\\) が最尤推定量の漸近共分散になる。

符号を落とさないこと。対数尤度そのものの Hessian は最大点で負定値なので、
その逆行列は分散にならない。負の対数尤度で書けば、最適化のために計算する Hessian が
そのまま情報行列になり、**最適化のために計算した量がそのまま統計的な誤差評価になる。**

## Rust の言語機構

### `argmin` の trait 設計を読む

`argmin` は「Rust で数値アルゴリズムを抽象化する」実例として読む価値がある。
見るべきなのは、**目的関数・勾配・Hessian をどう分離しているか**である。

問いの形で挙げる。

- 勾配を持つ問題と持たない問題を、**同じ型の階層でどう表すか。**
  「勾配が計算できる」を別トレイトにするのか、`Option` を返すメソッドにするのか
- **ソルバーと問題を分離**すると、ソルバーは問題の型に対して generic になる。
  そのとき状態（現在の \\(x\\)、勾配、反復回数、履歴）は誰が持つのか
- 反復の途中経過を外に出す仕組み（observer / callback）をどう型に載せるか

読むのは設計であって実装ではない。**読んだ後に自分の設計と比べる**のが目的で、
真似することではない。

### 勾配をどう受けるか——章6との境界

形を挙げる。

1. **関数として受ける**: `grad: impl Fn(&[f64]) -> Vec<f64>`。
   章1と同じで、\\(f\\) と \\(\nabla f\\) の整合は呼び出し側の責任
2. **トレイトのメソッドにする**: `trait Objective { fn value(&self)->f64; fn grad(&self)->Vec<f64>; }`。
   **1つの型が両方を持つので、食い違いが構造的に起きにくい**
3. **autodiff に生成させる**: \\(f\\) だけ書けば \\(\nabla f\\) が出る（章6）

**2と3の境界をどこに置くかがこの章の設計判断である。**
`Objective` トレイトを切っておけば、章6で「autodiff で `grad` を実装した型」を
足すだけで済むかもしれない。**そうなるように切れているかは、章6に来ないと分からない。**

## オラクル

| 関数 | 最小点 | 値 |
|---|---|---|
| Rosenbrock \\((1-x)^2 + 100(y-x^2)^2\\) | \\((1, 1)\\) | \\(0\\) |
| Himmelblau \\((x^2+y-11)^2+(x+y^2-7)^2\\) | \\((3,2)\\) ほか3点 | \\(0\\)（4つとも） |
| Beale, Booth, 球関数 \\(\sum x_i^2\\) | 既知 | — |

Rosenbrock は**最小点での Hessian の条件数が \\(\kappa \approx 2500\\)** である。
\\(H = \begin{pmatrix}802 & -400\\\\ -400 & 200\end{pmatrix}\\) である。

**最急降下が遅い主因はまさにこの \\(\kappa\\) である。** 曲がった谷を辿る段階は意外に短く、
反復の大半は谷底の局所二次領域で消費される。そこでは1反復あたりの関数値の減衰比が
\\(((\kappa-1)/(\kappa+1))^2\\) と数桁の精度で一致する——**理論がそのまま当たっている。**

ただし理論を反復回数の予測に使うなら、**どの時点から当てるか**に注意する。
初期の数百反復は漸近レートより速いので、初期値から当てると理論のほうが過大に出る。
途中を起点にすれば残り反復数を数%以内で当てられる。ここは実測して確かめるとよい。

**曲率が変わることの実害は別の場所にある。** 効くのは最急降下の反復回数ではなく
Newton 系のステップ受理のほうで、純粋 Newton は途中で初期値より悪い点へ飛んでから復帰する。
単調降下ではない。

Himmelblau は極小が4つあるので、初期値によって別の点に落ちる——
局所最適の存在を実感するのに使える。\\((3,2)\\) 以外の3点は無理数座標である。

`scipy.optimize.minimize` の結果を埋め込む形も取れるが、
上の関数は最小点が解析的に分かるのでオラクルは要らない。

## 完了条件

**Rosenbrock で最急降下・Newton・BFGS の反復回数を比較し、
条件数の悪い谷で最急降下がジグザグする様子を実際に出す。**

「実際に出す」は反復列 \\(\\{x_k\\}\\) を `examples/` でプロットすることを指す。
数字の表より、谷を斜めに跳ね返る軌跡を見るほうが早い。

実測（初期値 \\((-1.2, 1)\\)、Armijo backtracking、停止条件 \\(\\|\nabla f\\|_2 < 10^{-6}\\)）の**オーダー**:

| 手法 | 反復回数 |
|---|---|
| 最急降下 | \\(10^4\\) 台 |
| BFGS | \\(10^1\\) 台 |
| Newton（backtracking つき） | \\(10^1\\) 台 |
| Newton（純粋、大域化なし） | 1桁 |

**具体的な値は直線探索のパラメータで2倍以上動く**（\\(\rho\\)、\\(\alpha_0\\)、\\(\alpha\\) を毎回
リセットするか前回値から始めるか）。だから桁で見る。

**診断基準は「最急降下と他の3つの間に2〜3桁の差が出るか」に限ること。**
BFGS と大域化した Newton は同じ桁で、これが正常である。
「BFGS と Newton で桁が違わないから実装がおかしい」と判断すると、正しい実装を疑い続けることになる。

なお Rosenbrock のこの経路では Hessian が終始正定値なので、\\(\lambda I\\) 修正は一度も発動しない。
Newton の反復数を作っているのは backtracking だけである。
